# Приймання · observer-timezone

> Спека: docs/specs/observer-timezone.md
> Правило: критерій вважається виконаним лише з доказом (вивід команди, скріншот пристрою).
> Базовий зріз ДО правки (2026-08-01): `TZ=America/New_York npm test` → 342/345;
> `TZ=Europe/Kyiv npm test` → 345/345.

## A. Розрахунок (R1, R2)

**A1.** Для кожного з 10 міст `SKY_CITIES` і для кожного з поясів пристрою
`Europe/Kyiv`, `America/Los_Angeles`, `Australia/Sydney`, `UTC` тривалість дня
(`computeSunDetail(...).dayLengthMs`) **> 0**, а `sunrise < sunset`.
40 комбінацій, жодного винятку. Доказ: таблиця виводу.

**A2.** Для однієї локації результат `computeSunTimes` **побітно однаковий**
у всіх чотирьох поясах пристрою (порівняння за `toISOString()`).
Це головний критерій: розрахунок перестав залежати від машини.

**A3.** Те саме для `computeSunDetail`, `computeObservingWindow`,
`computeVisibleTonight`, `computeMilkyWayWindow`, `riseSetForLocalDay`.
Жодна з них не звертається до півночі пристрою для локації з відомим поясом.

**A4.** Контрольні точки на 2026-08-01 (пристрій `Europe/Kyiv`), які ДО правки
давали від'ємну добу — тепер додатну і правдоподібну для сезону:
Сідней (ДО: −13.53 год) → додатна, зимовий день у південній півкулі < 12 год;
Токіо (ДО: −10.06 год) → додатна;
Лос-Анджелес (ДО: −10.17 год) → додатна, літній день > 13 год.
Київ/Київ лишається +15.28 год ±1 хв (регресія не зачепила справний випадок).

**A5.** Пояс вшитого міста збігається з громадянським часом цього міста для дати
2026-08-01 (літній час): Київ UTC+3, Лондон UTC+1, Нью-Йорк UTC−4,
Лос-Анджелес UTC−7, Токіо UTC+9, Сідней UTC+10, Дубай UTC+4.
Провал критерію = використали `lon/15` замість реального поясу (розбіжність
58 хв для Києва, 53 хв для Лос-Анджелеса).

**A6.** Локація з `source: 'gps'` (координати без поясу) рахується за поясом пристрою;
результат для координат Києва на київському пристрої збігається з A4.

## B. Екран (R3, R4)

**B1.** Пристрій у `America/Los_Angeles`, локація — дефолтний Київ, перший запуск,
жодної взаємодії: рядок «захід» на головному і шторка Сонця показують київські години
(схід ~05:25, захід ~20:42 за київським годинником 2026-08-01), тривалість дня ≈ 15год 17хв.
Доказ: скріншот симулятора/пристрою з переставленим поясом.

**B2.** Коли пояс локації ≠ пояс пристрою, на екрані є видима ознака цього
(мітка поясу або підпис біля міста). Користувач не має підстав вважати час помилкою.
Ключі є і в `en`, і в `uk` блоці `src/i18n/messages.bundle.js`; хардкоду рядків немає.

**B3.** Штучно підсунута тривалість дня ≤ 0 рендериться як «—», а не як
«−9год −24хв». Доказ: юніт-тест на форматер.

## C. Тести й CI (R5, R6)

**C1.** `TZ=America/New_York npm test` → **345/345**. Було 342/345.

**C2.** Те саме зелене для `TZ=UTC`, `TZ=Australia/Sydney`, `TZ=America/Los_Angeles`
і `TZ=Europe/Kyiv`. П'ять прогонів, усі 345/345 (або більше, якщо додано тести).

**C3.** Тест 111 виправлено **у фікстурі**: літерали `new Date('2026-03-10')`
замінені на явні локальні дати. Дифф по `src/helpers/dailyRitual.js` — **порожній**.
Провал критерію = полагодили тест зміною продуктової логіки стріку.

**C4.** У CI (`.github/workflows`, job «Lint and Test») є крок прогону тестів
у поясі, відмінному від UTC. Доказ: посилання на зелений прогін після мержу.
