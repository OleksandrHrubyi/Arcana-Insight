# Bug log — 2026-06-23 (user click-through testing)

Bugs the user found by walking the app. Status as of this session.

## ✅ Fixed & verified (code) — commit on `main`

### 1. Menu "card of the day" launcher went to Home, not the daily card
- **Was:** `menu-daily-launcher` pushed `name: 'arcana'` (home/LandingScene).
- **Fix:** pushes `name: 'daily'` (DailyCardPage). `MenuComponent.vue`.

### 2. Bottom navigation disappeared on the Home screen
- **Cause:** regression from the `BlankLayout` meta-driven nav change — the Home route (`arcana` → LandingScene) was wrongly tagged `meta.hideBottomNav: true`, so the nav got hidden there.
- **Fix:** removed `hideBottomNav` from the `arcana` route (it's the one route that must always show nav). `routes.js`. Verified via Playwright: home shows nav, premium still hides it.

### 3. After buying Premium, the button stayed "Continue with Premium" and could re-open / cancel the purchase
- **Was:** `purchaseButtonLabel` ignored premium state; `onPurchase` had no already-premium guard → re-tapping re-opened a cancellable IAP.
- **Fix:** when `hasPremiumAccess`, the button reads "You're Premium" and acts as **close** (no re-purchase). `PremiumInfoComponent.vue` + i18n `premiumPage.billing.premiumActive`.

### 4. Personal Horoscope (non-premium) → infinite redirect loop to /premium
- **Cause:** `PersonalHoroscopePage` auto-called `generate()` on mount → `goPremium()` → push `/premium`; back/close returned here and re-redirected forever.
- **Fix:** mount no longer auto-generates for non-premium — it shows the lock panel; only the "Unlock Premium" CTA opens the paywall. `locale` watcher also guarded. `PersonalHoroscopePage.vue`.

## ⏳ Needs your input / dashboard (not fixable blind from the repo)

### 5b. Push: scheduled for 09:00 but arrives throughout the day; desktop gets nothing
- **Findings:** `register-device` stores `notify_hour/notify_minute/tz` in `push_devices`. `push-worker` sends to rows where `next_send_at <= now OR next_send_at IS NULL`, then calls the `push_mark_sent` RPC to reschedule. **But `push_mark_sent` and the cron that runs `push-worker` are dashboard-managed — not in this repo**, so I can't see/fix the actual time math.
  - Likely cause of "throughout the day": `next_send_at` isn't being set to the next `notify_hour` in the user's `tz` (stays NULL or drifts), so the worker fires whenever its cron runs.
  - "Desktop gets nothing": push is APNs/iOS only (`platform = 'ios'`); the web/desktop build has no web-push, so this is expected unless you want web push.
- **Need from you:** the SQL of the `push_mark_sent` function + the pg_cron schedule for `push-worker` (Supabase dashboard → Database → Functions / Cron). Then I can fix the time math.
