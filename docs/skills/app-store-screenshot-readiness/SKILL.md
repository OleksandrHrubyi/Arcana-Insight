# App Store Screenshot Readiness

Use this skill when a screen must look credible as a polished shipping mobile product.

## Goal

A screen that looks App Store-ready should feel:

- readable
- intentional
- premium
- calm
- clearly useful

It should not feel like a prototype, debug screen, or layered experiment.

## Visual Standards

1. Hierarchy
   - strong focal point
   - supporting content clearly secondary
   - no visual confusion about where to look first

2. Readability
   - no tiny body text
   - no dense helper paragraphs in critical areas
   - no low-value copy occupying premium space

3. Composition
   - avoid accidental overlaps
   - avoid cramped lower areas near nav
   - avoid too many cards with equal visual weight

4. Product clarity
   - screen must communicate what the app helps the user do
   - atmospheric styling is supporting, not primary

## Screenshot Review Questions

- Would this look trustworthy in an App Store screenshot?
- Does the screen look intentional, or patched together?
- Is the first action obvious?
- Is the text readable without zooming?
- Does the screen feel like a premium mobile product?

## Red Flags

- crowded lower half
- tiny labels carrying important meaning
- duplicated entry points
- multiple gradients/cards competing for attention
- hero blocked by added explanation panels
- too much explanation before action

## Completion Checklist

- first focal point is obvious
- content looks production-grade
- text is readable in screenshot form
- no overlapping or cramped composition
- the screen communicates user value fast

## Failure Mode Rule

If the screen would be embarrassing as an App Store screenshot, stop and simplify before adding anything else.
